This file provides guidance to AI coding agents working with this repository.

## Project Overview

**collie-core** is the Python core of Collie — a desktop AI assistant for
non-developers ("Your personal AI. With a dog."). It is a stripped fork of
nanobot (HKUDS/nanobot, MIT): the agent loop, LLM providers, tool registry,
MCP client, and WebSocket transport were kept; the CLI, slash commands,
developer tools (shell/filesystem/search/patch), platform channel bots, and
JSON config system were removed.

Two packages:

- `nanobot/` — the forked engine (loop, runner, providers, tools, bus,
  session, websocket channel, and the vendored messenger channels:
  telegram, whatsapp, slack, discord). Treat as adapted vendor code; keep
  changes surgical.
- `collie_core/` — Collie's own code: SQLite storage (`db.py`), settings
  bridge (`settings.py`), structured profile memory (`memory/`), life tools
  (`tools/`), first-class external connections (`connectors/`), the one-alpha
  legacy compatibility layer (`services/`), subagents (`subagents/`),
  automations (`automations/`), messengers (`messengers/`), desktop pet
  (`pet/`), IPC server (`ipc/`), and the runtime entry (`runtime.py`).

The Electron/React shell lives in the sibling repo folder `../collie-ui` and
talks to `collie_core.runtime` over a localhost WebSocket (default port 3818).

## Development Commands

```powershell
# From collie-core/ (Windows dev box; venv already exists)
.\.venv\Scripts\python.exe -m pytest tests -q          # full suite
.\.venv\Scripts\python.exe -m pytest tests\collie -q   # Collie-specific tests
.\.venv\Scripts\python.exe -m ruff check nanobot collie_core tests
.\.venv\Scripts\python.exe -m collie_core.runtime --port 3818   # run the core

# From ../collie-ui
npm run dev          # Electron app against dev core
npm run typecheck
npm run build
```

## Architecture Notes

- **Chat flow**: Electron renderer → `collie_core/ipc/server.py` (WebSocket
  JSON protocol) → `AgentLoop.process_direct` → provider → streamed deltas
  back as `thinking`/`delta`/`message` events → messages persisted in
  `~/.collie/collie.db` (`COLLIE_HOME` overrides the base dir).
- **Turn states**: RESTORE → COMPACT → BUILD → RUN → SAVE → RESPOND (the
  COMMAND state was removed with slash commands).
- **Context**: `ContextBuilder.BOOTSTRAP_FILES = [VISION.md, AGENTS.md,
  MEMORY.md]` from `~/.collie/workspace/`. `MEMORY.md` is regenerated by
  `collie_core.memory.ProfileStore` after every `remember`-tool write.
- **Settings**: SQLite `settings` table → `collie_core.settings.build_config`
  → engine `Config`. No JSON config files; secrets stay in the OS keychain
  (Electron `safeStorage`) and are injected per-process via IPC.
- **Auth**: three equal paths — ChatGPT OAuth (`openai_codex` provider),
  Claude OAuth (`collie_core/providers/claude_oauth.py`), or API key.
- **Tools**: engine built-ins (web_search, web_fetch, message, cron, image
  generation, MCP) + Collie tools discovered from `collie_core/tools` via
  `ToolLoader(collie_core.tools)`. In-app tools (shopping, budget, health,
  reminders, contacts) read the DB through module-level bindings
  (`bind_life_db`, `bind_reminders_db`, …) set by the runtime; MCP-backed
  tools (calendar, email, notes, smart home, documents) return guidance
  toward `mcp_<service>_*` tools once a service is connected.
- **Connections**: `collie_core/connectors/` owns the curated catalogue,
  official-MCP OAuth lifecycle, live probe, cached tool policy, and the sole
  runtime `ConnectorManager`. A catalogue entry is available only after the
  exact packaged artifact passes the complete provider acceptance matrix.
  `collie_core/services/` remains for one alpha as a compatibility shim for
  legacy rows, credentials, tools, IPC reads, and the packaged MCP probe. Do
  not add a second UI connection flow or remove that shim before the dedicated
  migration fixtures pass.
- **Subagents (Phase 3)**: `.md` files with YAML frontmatter in
  `~/.collie/workspace/subagents/`, mirrored to SQLite by
  `collie_core/subagents/loader.py`. The `call_subagent` tool spawns the
  engine's `SubagentManager` with the specialist prompt; results are
  announced back into the conversation.
- **Automations**: `collie_core/automations/scheduler.py` polls the DB every
  minute (schedules: `HH:MM`, `Www HH:MM`, `DD HH:MM`);
  `automations/custom.py` parses plain English into those schedules — no LLM
  required. When fired, the runtime's `_run_automation` runs the prompt
  through the loop, lands the result in a `🔔` conversation, broadcasts an
  `automation` event (OS notification), and fans out to messengers.
- **Messengers (Phase 4)**: the phone companion is Telegram/WhatsApp/Slack/
  Discord, not an app. Channel modules are vendored upstream nanobot code in
  `nanobot/channels/` (slash commands stripped to `/start` + `/help`;
  WhatsApp exposes `on_qr`/`on_status` hooks for the GUI).
  `collie_core/messengers/manager.py` owns lifecycle (settings keys
  `messengers.<name>.*`), secrets (runtime-injected via
  `set_messenger_secret`, keychain-backed on the shell side), outbound
  dispatch from the bus, chat mirroring into a `📱` desktop conversation per
  messenger, and automation delivery. `messengers/bus.py` (`CollieBus`)
  observes inbound for the mirror. Unknown DM senders get a pairing code
  (`nanobot/pairing`), approved in Settings → Phone via `approve_pairing`.
  The engine data dir (pairing.json, media) is anchored to `~/.collie` by
  `set_config_path` at runtime boot.
- **Thinking states**: dog-themed phrases in `collie_core/ipc/thinking.py`;
  never use corporate language in user-facing strings.

## Testing

- pytest with `asyncio_mode = "auto"`; tests mirror package structure.
- `tests/collie/test_e2e_phase1.py` … `test_e2e_phase4.py` are the phase
  gates: full IPC → loop → fake OpenAI endpoint → SQLite round trips. Keep
  them green. Phase 3's gate patches `connect_mcp_servers` so tests never
  spawn real `npx` MCP servers; Phase 4's gate swaps the Telegram channel
  for an in-process fake (never build real channel SDK clients in tests).
- Line length 100; lint with `ruff` (E, F, I, N, W; E501 ignored).

## Voice Rules (user-facing strings)

Collie speaks like a smart, loyal dog who can type: warm, first-person,
playful, never corporate. Errors say things like "Uh oh. I chased my tail on
that one." — never "An error occurred while processing your request."
